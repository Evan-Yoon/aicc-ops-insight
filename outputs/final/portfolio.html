| 공개 고객지원 데이터와 경쟁사 공개 지표를 기반으로 CLOVA AiCall 운영 KPI와 개선 인사이트를 도출한 AI PaaS 운영 분석 프로젝트
Situation

NAVER Cloud CLOVA AiCall은 음성 인식·NLP·TTS를 활용해 Inbound/Outbound 콜 업무를 AI 봇으로 처리하는 AI PaaS 상품이다. 운영 담당자는 고객 문의 유형, CS 현황, 경쟁사 동향, 품질관리 지표를 지속 모니터링해야 하지만, 이를 체계화한 운영 분류 구조가 부재했다.

  • 공개 데이터 부재: 실제 AiCall 도입 문의 데이터는 공개되지 않아 운영 지표 구조화를 위한 방법론이 필요했음
  • 경쟁사 격차: KT·LGU+·SKT는 수주액, 고객사 수, 매출 목표 등 시장성 지표를 적극 공개하는 반면, NAVER Cloud의 외부 공개 운영 지표는 상대적으로 제한적
  • 운영 구조화 필요: 고객 문의 유형을 AiCall Main/Global/Repair 시나리오, Auto QA와 연결하는 분류 체계가 부재
Task

AICC 운영 관점의 4가지 분석 목표:

  • 공개 고객지원 데이터셋을 AICC 운영 레이블로 재분류하고, 운영 KPI로 전환하는 방법론 설계
  • CLOVA AiCall Main / Global / Repair 시나리오 구조와 문의 유형을 연결해 시나리오 설계 우선순위 도출
  • KT, LGU+, SKT/SK AX 경쟁사 공개자료를 기반으로 AICC 시장 벤치마크 점수화
  • 운영 담당자 관점의 도입 적합도 점수화 · 운영 워크플로우 · KPI 리포트 개선안 도출 및 문서화
Action
① 데이터 수집 및 전처리
  • HuggingFace Bitext 고객지원 데이터셋 29,872건 로드 및 AICC 운영 관점 정규화
  • NAVER CLOVA AiCall 공식 가이드 분석 → Contact Center / Agent / Channel 구조, 통계 지표, 시나리오 구조 확인
  • KT, LGU+, SKT/SK AX 공개 기사 및 공식 자료 수집 → competitor_metrics.csv 35건+ 정리
② 문의 유형 분류 (Rule-based Classification)
  • 8개 AICC 운영 레이블 정의: 업무 처리 요청 / 결제·청구 / 계정·인증 / 상담원 연결 / 장애·오류 / 불만·클레임 / FAQ·단순 안내 / 기타
  • 키워드 우선순위 기반 Python 분류기 구현 → 각 레이블을 AiCall 시나리오 유형으로 매핑 (Main / Global / Repair / Auto QA)
③ 운영 KPI 점수화
  • 8개 지표 산출: 자동화 적합도 · 상담원 연결 필요도 · Auto QA 필요도 · 시나리오 복잡도 · Main / Global / Repair 시나리오 필요도 · 운영 우선순위 종합 점수
④ 경쟁사 벤치마크 점수화
  • 5개 평가 지표(시장성 · 도입 레퍼런스 · 운영 효율 · 기능 고도화 · 운영 품질 관리) 기준 8개사 공개 근거 점수화
